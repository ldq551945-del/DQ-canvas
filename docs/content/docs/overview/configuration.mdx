# 配置说明

配置分为两类：服务器环境变量和管理员后台配置。数据库连接、加密密钥、数据目录和代理等部署级配置使用环境变量；模型渠道、逻辑模型、SMTP、积分、套餐和支付在后台维护。

## 核心环境变量

| 变量                           | 必填            | 说明                                                                          |
| ------------------------------ | --------------- | ----------------------------------------------------------------------------- |
| `NEXT_PUBLIC_SITE_URL`         | 生产必填        | 外部可访问的站点地址，生产使用 HTTPS，不带尾部 `/`                            |
| `VOZEB_PRO_DATABASE_PROVIDER`  | 是              | 生产使用 `postgres`；`file` 仅用于单机文件模式体验                            |
| `DATABASE_URL`                 | PostgreSQL 必填 | PostgreSQL 连接串；Docker 内数据库 Host 使用 `postgres`                       |
| `VOZEB_PRO_DATABASE_POOL_MAX`  | 否              | 连接池上限，默认 10，低内存或托管数据库可设置 5                               |
| `VOZEB_PRO_DATABASE_SSL`       | 否              | 本机/Docker 通常为 0，云 PostgreSQL 按要求使用 1                              |
| `VOZEB_PRO_ENCRYPTION_KEY`     | 生产必填        | 64 位十六进制或精确 32 字节 Base64 密钥，部署后必须保持稳定                   |
| `VOZEB_PRO_INTERNAL_ORIGIN`    | 推荐            | 服务端回调自身 API，Docker 默认 `http://127.0.0.1:3000`                       |
| `VOZEB_PRO_DATA_DIR`           | 否              | 服务器媒体和文件模式数据目录                                                  |
| `VOZEB_PRO_COOKIE_SECURE`      | 否              | 留空自动判断；特殊代理可强制 `true/false`                                     |
| `VOZEB_PRO_TRUSTED_PROXY_HOPS` | 否              | 速率限制读取代理 IP 时信任的代理层数；直连保持 `0`，单层 Nginx/Caddy 使用 `1` |
| `VOZEB_PRO_MAINTENANCE_TOKEN`  | 推荐            | 外部计划任务调用维护接口的 Bearer Token，至少 32 个字符                       |
| `FFMPEG_PATH`                  | 否              | 本机 FFmpeg 不在 PATH 时填写；Docker 已内置 FFmpeg                            |

## PostgreSQL

源码运行示例：

```dotenv
VOZEB_PRO_DATABASE_PROVIDER=postgres
DATABASE_URL=postgres://vozeb_pro:password@localhost:5432/vozeb_pro
VOZEB_PRO_DATABASE_POOL_MAX=10
VOZEB_PRO_DATABASE_SSL=0
```

主 Compose 会根据这些变量创建数据库：

```dotenv
POSTGRES_DB=vozeb_pro
POSTGRES_USER=vozeb_pro
POSTGRES_PASSWORD=replace-with-a-strong-database-password
```

安装页不会保存数据库密码。GET 状态检查只执行连接与表存在性查询；只有点击“初始化表结构”才会创建 `vozeb_pro_` 前缀表。加密密钥无效时初始化和首个管理员注册都会被阻止。

使用宝塔宿主机 PostgreSQL 时，应用通过 `docker-compose.baota.yml` 的 host 网络连接 `127.0.0.1:5432`；不要同时启动默认 Compose 中的 PostgreSQL 服务。

## 站点地址与代理

需要支付回调、上游读取站内参考素材或 HTTPS Cookie 时，配置真实域名：

```dotenv
NEXT_PUBLIC_SITE_URL=https://vozeb-pro.example.com
```

上游模型需要网络代理时：

```dotenv
HTTPS_PROXY=http://proxy-host:7890
HTTP_PROXY=http://proxy-host:7890
ALL_PROXY=http://proxy-host:7890
```

代理变量只作用于服务端请求，不会下发给浏览器。

## 模型渠道与逻辑模型

进入 `管理员后台 -> 上游配置 -> 模型渠道`：

1. 新建渠道并填写协议、Base URL、API Key 和模型列表。
2. 使用文本、图片、视频、音频能力检测确认真实接口可用。
3. 创建用户侧逻辑模型，选择能力类型。
4. 为逻辑模型添加一个或多个渠道绑定、上游模型和优先级。
5. 设置默认文本、图片、视频和音频逻辑模型。

默认文本模型同时用于工作台 Agent、Canvas 规划和创作复盘。渠道 API Key 通过服务端保存，普通用户只看到逻辑模型名称。

## 媒体存储

外部存储关闭时，图片、视频和音频写入 `VOZEB_PRO_DATA_DIR`。用户上传和长期产物位于 `reference-assets/permanent/YYYY/MM/DD/{images|videos|audio}`，生成日志媒体位于 `generation-assets/permanent/YYYY/MM/DD/...`；临时参考素材位于 `reference-assets/temporary/...`，默认 24 小时过期。容器部署必须持久化整个数据目录。

管理员在 `系统管理 -> 本地媒体` 查看本机文件、大小、来源、引用和临时期限，并可单删、批量删除或清理过期文件。在 `系统管理 -> 外部存储` 可配置通用 S3 兼容 Endpoint、Region、Bucket、Access Key、Secret Key、对象前缀和 path-style 模式，适配 AWS S3、阿里云 OSS、腾讯云 COS、MinIO 等兼容服务；`系统管理 -> 数据备份` 提供脱敏业务备份导入导出。

开启外部存储后，新上传和新生成媒体只写对象存储，本地不保留持久副本；关闭后新媒体恢复本地写入。历史媒体始终按登记的 Provider 读取，不会因当前开关改变位置。后台可分批迁移已有本地媒体，只有对象上传和登记成功后才删除本地源文件。

## SMTP 与注册

SMTP 在后台 `账号与邮箱` 配置。建议先测试邮箱，再开启邮箱注册。注册验证码、找回密码和邮箱换绑会共用该 SMTP 配置。

## 支付

后台支持 Stripe、支付宝、微信支付、PayPly 和人工确认。密钥可以保存在后台加密配置中，也可以由环境变量提供兜底。回调入口：

```text
/api/billing/webhooks/stripe
/api/billing/webhooks/alipay
/api/billing/webhooks/wechat
/api/billing/webhooks/payply
/api/billing/webhooks/custom
```

完整支付变量见仓库根目录 `.env.example`。生产启用前必须验证下单、回调验签、订单开通、退款和账单对账。

待支付订单会在用户或管理员读取订单时自动检查并关闭。生产环境还应配置外部调度，每 5 分钟调用一次维护接口，使无人访问时也能及时清理：

```bash
curl -fsS -X POST \
  -H "Authorization: Bearer $VOZEB_PRO_MAINTENANCE_TOKEN" \
  https://vozeb-pro.example.com/api/maintenance/billing-orders/expire
```

宝塔使用“计划任务 -> Shell 脚本”，Docker 可使用宿主机 Cron，云部署使用平台 Scheduler。接口采用同一令牌和幂等批处理，不依赖单机进程定时器；未配置令牌时维护接口保持关闭。系统超时关闭的订单在支付商确认真实付款后仍可安全完成开通，管理员手动关闭的订单不会被重新打开。

## 配置检查顺序

1. `/install` 显示 PostgreSQL 与 schema 正常。
2. 管理员账号可登录。
3. 文本默认模型通过能力检查。
4. 图片/视频/音频按启用能力逐项检查。
5. 需要参考素材时检查站点域名可被上游渠道读取。
6. 检查 `VOZEB_PRO_DATA_DIR` 可写且已挂载持久数据卷。
7. SMTP 和支付分别通过后台测试入口。
