# 配置说明

配置分为两类：服务器环境变量和管理员后台配置。数据库连接、加密密钥、数据目录和代理等部署级配置使用环境变量；模型渠道、逻辑模型、SMTP、积分、套餐和支付在后台维护。

## 核心环境变量

| 变量                                       | 必填             | 说明                                                                                  |
| ------------------------------------------ | ---------------- | ------------------------------------------------------------------------------------- |
| `NEXT_PUBLIC_SITE_URL`                     | 生产必填         | 外部可访问的站点地址，生产使用 HTTPS，不带尾部 `/`                                    |
| `NEXT_PUBLIC_TLDRAW_LICENSE_KEY`            | 商业部署可选     | tldraw 生产 License Key；必须在 Next.js 或 Docker 镜像构建阶段提供                     |
| `DQ_DATABASE_PROVIDER`              | 是               | 生产使用 `postgres`；`file` 仅用于单机文件模式体验                                    |
| `DATABASE_URL`                             | PostgreSQL 必填  | PostgreSQL 连接串；Docker 内数据库 Host 使用 `postgres`                               |
| `DQ_DATABASE_POOL_MAX`              | 否               | 连接池上限，默认 10，低内存或托管数据库可设置 5                                       |
| `DQ_DATABASE_SSL`                   | 否               | 本机/Docker 通常为 0，云 PostgreSQL 按要求使用 1                                      |
| `DQ_ENCRYPTION_KEY`                 | 生产必填         | 64 位十六进制或精确 32 字节 Base64 密钥，部署后必须保持稳定                           |
| `DQ_INTERNAL_ORIGIN`                | 推荐             | 服务端回调自身 API，Docker 默认 `http://127.0.0.1:3000`                               |
| `DQ_DATA_DIR`                       | 否               | 服务器媒体和文件模式数据目录                                                          |
| `DQ_COOKIE_SECURE`                  | 否               | 留空自动判断；特殊代理可强制 `true/false`                                             |
| `DQ_TRUSTED_PROXY_HOPS`             | 否               | 速率限制读取代理 IP 时信任的代理层数；直连保持 `0`，单层 Nginx/Caddy 使用 `1`         |
| `DQ_MAINTENANCE_TOKEN`              | 生产推荐         | 生成 Worker 与外部计划任务调用维护接口的 Bearer Token，至少 32 个字符                 |
| `DQ_WORKER_API_ORIGIN`              | 独立 Worker 可选 | Worker 调用主应用的站内地址；Compose 使用 `http://app:3000`，Render 注入私网 hostport |
| `DQ_GENERATION_WORKER_ID`           | 否               | 生成 Worker 稳定标识；留空时由主机名和进程号生成                                      |
| `DQ_GENERATION_WORKER_INTERVAL_MS`  | 否               | 恢复批次轮询间隔，默认 2000ms                                                         |
| `DQ_GENERATION_WORKER_LANES`        | 否               | 单个 Worker 并行恢复通道数，默认 2                                                    |
| `DQ_GENERATION_WORKER_HEARTBEAT_MS` | 否               | Worker 心跳间隔，默认 15000ms                                                         |
| `DQ_GENERATION_WORKER_STALE_MS`     | 否               | 就绪检查判定 Worker 失联的窗口，默认 90000ms                                          |
| `DQ_GENERATION_WEBHOOK_SECRET`      | 回调可选         | 通用生成回调 HMAC-SHA256 密钥，启用时至少 32 个字符                                   |
| `DQ_APP_URL`                        | 文档站可选       | 独立文档站使用的主应用地址，使文档 favicon 跟随后台站点图标                           |
| `DQ_REMBG_URL`                      | 默认 Compose 可选；低内存必填 | 留空时标准/外部数据库 Compose 使用 `http://rembg:7000`，宝塔使用 `http://127.0.0.1:7000`；低内存部署填写仅内网可达的外部地址 |
| `DQ_REMBG_INTERNAL_TOKEN`           | 跨主机推荐       | rembg sidecar 的 Bearer Token；与 sidecar 配置一致，只保存在服务端环境变量             |
| `DQ_REMBG_IMAGE`                    | 否               | Compose 使用的 rembg 镜像，默认 `ghcr.io/dao-qin/dq-rembg:latest`                       |
| `DQ_REMBG_MODEL`                    | 否               | `/readyz` 启动基线模型，默认 `silueta`；画布 V3 任务可从镜像内固定白名单手动选模       |
| `DQ_REMBG_CONCURRENCY`              | 否               | rembg 推理并发，默认且硬限制为 1；其他图片、视频、文本任务不受此槽位限制               |
| `DQ_REMBG_CPUS`                     | 否               | Compose 为 sidecar 设置的 CPU 上限，默认 `2.0`；同时写入普通 Compose 与 `deploy.resources` |
| `DQ_REMBG_MEMORY_LIMIT`             | 否               | Compose 为 sidecar 设置的内存上限，默认 `5g`；同时写入普通 Compose 与 `deploy.resources` |
| `DQ_REMBG_OMP_NUM_THREADS`          | 否               | 单次 CPU 计算线程数，默认 2；Compose 同步到 ONNX、OpenMP、OpenBLAS 与 MKL              |
| `DQ_REMBG_ONNX_INTER_OP_THREADS`    | 否               | ONNX inter-op 线程，固定为 1                                                           |
| `DQ_REMBG_ALPHA_MATTING_TILE_PIXELS`| 否               | 原尺寸 Alpha Matting 单块像素预算，默认 1,048,576；控制单块求解内存，不限制整图或输出尺寸 |
| `DQ_REMBG_TIMEOUT_SECONDS`          | 否               | 单次推理超时，默认 120 秒                                                              |
| `DQ_REMBG_QUEUE_TIMEOUT_SECONDS`    | 否               | 等待推理槽位超时，默认 30 秒                                                           |
| `DQ_REMBG_CANCEL_TIMEOUT_MS`        | 否               | BFF 等待 sidecar 完成子进程清理的超时，默认 15000ms                                   |
| `DQ_REMBG_CANCEL_TOMBSTONE_SECONDS` | 否               | sidecar 保留取消标记的时间，默认 600 秒，最大 3600 秒                                  |
| `FFMPEG_PATH`                              | 否               | 本机 FFmpeg 不在 PATH 时填写；Docker 已内置 FFmpeg                                    |
| `FFPROBE_PATH`                             | 否               | 可选的 FFprobe 路径；默认使用 `FFMPEG_PATH` 同目录二进制或系统 PATH                   |
| `DQ_CONTENT_MODERATION_PROVIDER`    | 否               | 作品审核信号 Provider：`manual`、`keywords` 或 `http`，默认人工审核                   |
| `DQ_CONTENT_MODERATION_KEYWORDS`    | keywords 可选    | 逗号或换行分隔的风险关键词，只生成后台复核信号                                        |
| `DQ_CONTENT_MODERATION_URL`         | http 必填        | 外部内容审核 HTTP 地址；服务端以 3 秒超时发送公开草稿字段                             |
| `DQ_CONTENT_MODERATION_API_KEY`     | http 可选        | 外部审核 Bearer Token，仅保存在服务器环境变量                                         |

## PostgreSQL

源码运行示例：

```dotenv
DQ_DATABASE_PROVIDER=postgres
DATABASE_URL=postgres://dq:password@localhost:5432/dq
DQ_DATABASE_POOL_MAX=10
DQ_DATABASE_SSL=0
```

主 Compose 会根据这些变量创建数据库：

```dotenv
POSTGRES_DB=dq
POSTGRES_USER=dq
POSTGRES_PASSWORD=replace-with-a-strong-database-password
```

安装页不会保存数据库密码。GET 状态检查只执行连接与表存在性查询；只有点击“初始化表结构”才会创建 `dq_` 前缀表。加密密钥无效时初始化和首个管理员注册都会被阻止。

使用宝塔宿主机 PostgreSQL 时，应用通过 `docker-compose.baota.yml` 的 host 网络连接 `127.0.0.1:5432`；不要同时启动默认 Compose 中的 PostgreSQL 服务。

## 0.0.3 发布部署要求

安装过 0.0.2 的用户必须停止旧服务并删除旧数据库或数据库卷，然后重新拉取 0.0.3 代码或镜像并重新安装项目。0.0.3 不支持沿用旧数据库或原地升级；删除旧数据库会清除其中的数据。

启动 0.0.3 后访问 `/install`，执行“初始化表结构”并创建首个管理员，再检查 `/api/health/ready` 返回 200 和 Worker 心跳。重新生成至少 32 个字符的 `DQ_MAINTENANCE_TOKEN`，让 App 与 `generation-worker` 使用同一个值；生产环境重新设置 `DQ_ENCRYPTION_KEY` 并妥善保存。

0.0.3 只按当前 Schema 初始化固定 `dq_` 前缀表，不包含 0.0.2 数据迁移或旧任务修复逻辑。Render 的 0.0.3 Blueprint 使用付费 Web/Worker 与持久数据库/磁盘，安装前请确认平台费用。

## 作品内容审核信号

作品提交审核后仍必须由管理员在“内容运营 -> 作品管理”中作出通过或驳回决定。默认 `manual` 只记录“等待人工审核”；`keywords` 根据部署方自定义词表生成风险标签；`http` 将标题、说明、分类和标签发送到部署方配置的中立 HTTP Provider。三种模式都不会自动公开作品，外部 Provider 失败时回退为人工复核信号。

```dotenv
DQ_CONTENT_MODERATION_PROVIDER=keywords
DQ_CONTENT_MODERATION_KEYWORDS=风险词一,风险词二
```

使用 `http` 时必须根据运营地区、隐私政策和供应商协议确认数据处理范围；API Key 不得放入普通用户设置或浏览器请求。

## 站点地址与代理

需要支付回调、上游读取站内参考素材或 HTTPS Cookie 时，配置真实域名：

```dotenv
NEXT_PUBLIC_SITE_URL=https://store.dqin-666zj.top
```

画布绘图使用 tldraw。需要移除生产水印时，在源码构建或镜像构建阶段配置 `NEXT_PUBLIC_TLDRAW_LICENSE_KEY`；它是浏览器公开配置，运行中的预构建镜像不会读取并重新编译该值。GitHub 镜像工作流从同名 Repository Secret 注入，本地 Compose 构建从 `.env` 注入。

独立部署文档站时，可在文档容器设置主应用地址：

```dotenv
DQ_APP_URL=https://store.dqin-666zj.top
```

文档站的 `/favicon.ico` 会通过主应用同名入口读取后台配置的站点图标；未配置时继续使用文档镜像内置 Logo，不会连接主应用数据库。

管理员后台的“使用文档”是主应用 `3000` 内的管理员操作说明，普通用户 `/help` 是独立的创作教程；开发、部署和数据库等技术文档继续由独立文档站 `3001` 提供，三者互不混用。

上游模型需要网络代理时：

```dotenv
HTTPS_PROXY=http://proxy-host:7890
HTTP_PROXY=http://proxy-host:7890
ALL_PROXY=http://proxy-host:7890
```

代理变量只作用于服务端请求，不会下发给浏览器。

## Canvas 抠图服务

Canvas 图片组件的“抠图”操作由 rembg sidecar 执行。主应用 BFF 先验证当前用户和
Canvas 归属，再以原始图片字节调用：

```text
POST ${DQ_REMBG_URL}/v1/remove
Content-Type: image/png | image/jpeg | image/webp
Authorization: Bearer ${DQ_REMBG_INTERNAL_TOKEN}  # 配置 Token 时发送
```

成功响应为 `image/png`，并带有实际任务模型的 `x-rembg-model`、
`x-rembg-input-width` 和 `x-rembg-input-height` 响应头。V3 参数快照可逐任务选择
`u2net`（通用）、`isnet-general-use`（高精通用）、`u2net_human_seg`（人像）、
`isnet-anime`（动漫插画）或默认的 `silueta`（轻量通用）；V1/V2 历史快照仍按 `u2net` 读取。
自定义表同时提供 rembg 官方 UI 的“官方精细”组合：Alpha Matting 开启、前景/背景
阈值 240/10、边缘细化 40、蒙版后处理开启。所有新任务强制输出带 Alpha 通道的透明
RGBA PNG；历史已完成的蒙版或纯色素材保持可读，不会重写。

服务端限制单张输入和输出各 30MB并拒绝动图；EXIF 校正后最长边超过 2048px 或源图
超过 64,000,000 像素时，主应用会等比缩至最长边 2048px，小图不会放大。sidecar 在
模型入口再次验证 64,000,000 像素和 2K 上限。用户级每分钟 30 次、同源节点限制和结果
写入媒体库由 BFF 负责。前端只拿到主应用返回的媒体引用，不应读取 sidecar 地址或 Token。

默认 Compose 会创建 `rembg` 容器；低内存 Compose 不会创建该容器，必须先准备外部
服务。五个白名单模型已在镜像构建阶段下载并校验到 `/models`，标准 Compose 不再给
该路径挂载命名卷，避免旧卷或空卷遮蔽镜像内权重。更新模型白名单时需要拉取新版
sidecar 镜像，而不是修改任意请求参数。模型权重与 rembg 软件的许可证分开核对：
软件为 MIT，权重条款以各模型卡为准，不要把软件许可证自动套用到模型权重。

标准、本地构建、外部数据库和宝塔 Compose 默认把 rembg 限制为 `2.0` CPU 与 `5g`
内存，并把同一变量同时写入顶层 `cpus`/`mem_limit` 和
`deploy.resources.limits`：前者覆盖普通 `docker compose`，后者覆盖采用 Deploy
资源语义的部署方式。这里声明的是容器可使用的上限，不是预留量；主机仍需为 App、
Worker、数据库和系统保留资源。默认 `DQ_REMBG_OMP_NUM_THREADS=2`，并同步到
OpenMP、OpenBLAS 与 MKL，使 ONNX 推理和 Alpha 求解都可使用两个 CPU 核心；
`DQ_REMBG_CONCURRENCY=1` 表示全站同一时间只执行一个 rembg 推理；PostgreSQL advisory
lock 与任务租约保证多 worker 不会突破该槽位，其余任务按 `created_at, id` FIFO 排队。
`DQ_REMBG_ALPHA_MATTING_TILE_PIXELS=1048576` 限制每个 Alpha 求解分块的像素量和内存峰值。

Clash Verge / Mihomo 使用 TUN Fake-IP 模式时，容器中的公网域名可能解析为 `198.18.0.0/15`，而不是目标站点的真实公网地址。确认 Docker 容器的直接外网请求已经由 Clash 接管后，可以显式开启：

```dotenv
DQ_ALLOW_FAKE_IP_DNS=1
```

该开关只接受“域名 DNS 解析结果全部位于 Clash Fake-IP 网段”的地址；直接填写 `198.18.x.x`、localhost、内网 IP 和云元数据域名仍会被拒绝。未使用 Fake-IP DNS 时保持 `0`。

## 模型渠道与逻辑模型

进入 `管理员后台 -> 上游配置 -> 模型渠道`：

页面分为“渠道管理、协议中心、逻辑模型、验证记录”四个工作区。新渠道使用固定六步向导：

1. 选择内置协议或自定义协议。Seedance 2.0（SD2）、火山方舟视频、Seedance 2.0 特价版和 Stable Diffusion（SD）是独立协议，不能混用。
2. 填写渠道名称、Base URL 和协议需要的凭据。Stable Diffusion A1111/Forge 默认无需 API Key；自定义协议可选择无需鉴权、Bearer、X-API-Key 或自定义 Header。
3. 拉取并合并模型目录；上游没有目录接口时手工填写模型 ID，后续同步不会删除手工模型。
4. 按文本、图片、视频和音频执行真实能力检测。媒体检测可能产生上游费用。
5. 把上游模型绑定到已有逻辑模型，或创建稳定逻辑模型 ID，并按需设为该能力的默认模型。
6. 复核协议、模型、验证结果和逻辑绑定；至少一项能力验证通过且已有绑定后再启用渠道，也可以先保存为停用草稿。

未知上游选择“自定义协议”，粘贴官方文档 URL、完整 cURL、请求 JSON 和成功响应 JSON。系统先做确定性解析，在默认文本模型可用时生成受固定 Schema 约束的补充草稿；草稿应用到具体模型后仍需管理员复核和真实检测。当前草稿保存在具体渠道中，不提供跨渠道的全局版本发布或回滚。

默认文本模型同时用于工作台 Agent、Canvas 规划和创作复盘。渠道 API Key 通过服务端保存，普通用户只看到逻辑模型名称。

## 生成任务 Worker 与回调

页面读取只会低成本唤醒当前任务。生产环境还需要常驻 `generation-worker`，使用户关闭页面后仍能使用已保存的上游任务 ID 继续查询并登记结果。默认、宝塔、低内存、外部数据库和本地 Compose 均声明了独立 Worker 服务；源码开发和 `npm start` 由应用启动脚本监督 Worker，也可以单独运行：

```bash
cd web
npm run worker:generation
```

Worker 与主应用必须使用同一个至少 32 字符的 `DQ_MAINTENANCE_TOKEN`。独立部署 Worker 时再设置 `DQ_WORKER_API_ORIGIN`；同一实例的 Worker ID 应保持稳定，便于就绪检查和故障诊断。`/api/health/ready` 会把缺少维护令牌、从未收到心跳或心跳过期报告为生成 Worker 未就绪。

上游支持回调时，可设置 `DQ_GENERATION_WEBHOOK_SECRET` 并让上游调用 `/api/generation-webhooks/{channelId}`。回调原始 JSON 使用该密钥做 HMAC-SHA256 签名；事件 ID 与上游任务 ID 必须稳定。回调只推进已有图片、视频或音频任务，不能代替任务创建；未匹配事件会保留用于对账。该幂等处理要求 PostgreSQL。

## 媒体存储

外部存储关闭时，图片、视频和音频写入 `DQ_DATA_DIR`。用户上传和长期产物位于 `reference-assets/permanent/YYYY/MM/DD/{images|videos|audio}`，生成日志媒体位于 `generation-assets/permanent/YYYY/MM/DD/...`；临时参考素材位于 `reference-assets/temporary/...`，默认 24 小时过期。容器部署必须持久化整个数据目录。

管理员在 `系统管理 -> 本地媒体` 查看本机文件、大小、来源、引用和临时期限，并可单删、批量删除或清理过期文件。在 `系统管理 -> 外部存储` 可配置通用 S3 兼容 Endpoint、Region、Bucket、Access Key、Secret Key、对象前缀和 path-style 模式，适配 AWS S3、阿里云 OSS、腾讯云 COS、MinIO 等兼容服务；`系统管理 -> 数据备份` 提供脱敏业务备份导入导出。

开启外部存储后，新上传和新生成媒体只写对象存储，本地不保留持久副本；关闭后新媒体恢复本地写入。历史媒体始终按登记的 Provider 读取，不会因当前开关改变位置。后台可分批迁移已有本地媒体，只有对象上传和登记成功后才删除本地源文件。

## SMTP 与注册

SMTP 在后台 `账号与邮箱` 配置。建议先测试邮箱，再开启邮箱注册。注册验证码、找回密码和邮箱换绑会共用该 SMTP 配置。

## 支付

后台支持 Stripe、支付宝、微信支付、PayPly 和人工确认。支付宝始终是一个用户支付渠道，管理员在“支付渠道”中使用“接入方式”二选一配置“官方支付”或“当面付”：官方支付跳转电脑网站收银台，当面付返回扫码二维码，两种方式共用 App ID、RSA2 回调验签和退款配置，不能同时启用。支付宝大陆支付商品使用人民币 `CNY`，非 CNY 订单会在请求上游前拒绝。密钥可以保存在后台加密配置中，也可以由环境变量提供兜底；环境变量 `DQ_ALIPAY_MODE` 可填写 `official`（默认）或 `face_to_face`。后台的回调、支付成功返回和取消返回地址均可留空，系统会自动使用当前网站地址；只有需要改用其他域名或自定义页面时才覆盖。当面付不使用同步返回地址。回调入口：

```text
/api/billing/webhooks/stripe
/api/billing/webhooks/alipay
/api/billing/webhooks/wechat
/api/billing/webhooks/payply
/api/billing/webhooks/custom
```

完整支付变量见仓库根目录 `.env.example`。生产启用前必须验证下单、回调验签、订单开通、退款和账单对账。

待支付订单会在用户或管理员读取订单时自动检查并关闭。生产环境还应配置外部调度，每 5 分钟调用一次维护接口，使无人访问时也能及时清理：

```bash
curl -fsS -X POST \
  -H "Authorization: Bearer $DQ_MAINTENANCE_TOKEN" \
  https://store.dqin-666zj.top/api/maintenance/billing-orders/expire
```

宝塔使用“计划任务 -> Shell 脚本”，Docker 可使用宿主机 Cron，云部署使用平台 Scheduler。接口采用同一令牌和幂等批处理，不依赖单机进程定时器；未配置令牌时维护接口保持关闭。系统超时关闭的订单在支付商确认真实付款后仍可安全完成开通，管理员手动关闭的订单不会被重新打开。

## 配置检查顺序

1. `/install` 显示 PostgreSQL 与 schema 正常。
2. 管理员账号可登录。
3. 文本默认模型通过能力检查。
4. 图片/视频/音频按启用能力逐项检查。
5. 需要参考素材时检查站点域名可被上游渠道读取。
6. 检查 `DQ_DATA_DIR` 可写且已挂载持久数据卷。
7. SMTP 和支付分别通过后台测试入口。
