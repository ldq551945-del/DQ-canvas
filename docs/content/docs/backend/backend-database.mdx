# 数据库结构

VOZEB PRO 商业版默认使用 PostgreSQL 作为主库。数据库初始化 SQL 由 `web/src/lib/server/database/schema.ts` 维护，服务端统一通过 `web/src/lib/server/database/` 下的 Repository 访问主库。

## 环境变量

```bash
VOZEB_PRO_DATABASE_PROVIDER=postgres
DATABASE_URL=postgres://vozeb_pro:change-me@localhost:5432/vozeb_pro
VOZEB_PRO_DATABASE_POOL_MAX=10
VOZEB_PRO_DATABASE_SSL=0
VOZEB_PRO_ENCRYPTION_KEY=64位十六进制或32字节Base64密钥
```

首次部署后访问 `/install`。状态 GET 只读检查 `DATABASE_URL`、PostgreSQL 连接、表结构和管理员数量，不执行 DDL；表结构由安装页 POST 初始化操作显式创建。有效的 32 字节加密密钥是初始化和创建首个管理员的前置条件。

如果只需要本地文件存储体验，可显式配置：

```bash
VOZEB_PRO_DATABASE_PROVIDER=file
```

## 表名前缀

VOZEB PRO 的 PostgreSQL 真实表名统一使用项目名前缀 `vozeb_pro_`。业务代码里仍然使用逻辑表名，例如 `users`、`billing_orders`、`generation_logs`；数据库执行层会统一映射为真实表名：

- `users` -> `vozeb_pro_users`
- `billing_orders` -> `vozeb_pro_billing_orders`
- `generation_logs` -> `vozeb_pro_generation_logs`

这样同一个 PostgreSQL 数据库里即使存在其他业务表，也能清楚区分 VOZEB PRO 的数据。无前缀表不会被自动删除；当前部署和后续读写只使用 `vozeb_pro_` 前缀表。

## 核心表

- `vozeb_pro_schema_migrations`：已应用的数据库结构版本。
- `vozeb_pro_app_settings`：站点、注册、邮箱、积分、生成、支付配置、逻辑模型目录、渠道绑定和默认模型等全局设置；`logical_models` JSONB 保存用户可见模型及其能力、上游模型、渠道、启用状态和优先级。
- `vozeb_pro_object_storage_settings`：S3 兼容外部存储单例配置，保存启用状态、Endpoint、Region、Bucket、对象前缀、path-style 模式及加密后的 Access Key/Secret Key；管理接口只返回密钥是否已配置，不回传明文。
- `vozeb_pro_system_model_channels`：系统模型渠道、加密后的 API Key、模型列表和高级配置。
- `vozeb_pro_entitlement_plans`：商业套餐权益、每日额度、调用限制和功能标记；新用户不再通过套餐获得注册初始积分。
- `vozeb_pro_users`：用户账号、角色、状态、当前套餐、积分余额和密码哈希。
- `vozeb_pro_sessions`：登录会话 token 哈希和过期时间。
- `vozeb_pro_account_deletion_requests`：账号注销申请、用户资料快照、申请状态、管理员处理备注与处理人快照；同一用户同一时间只能存在一条待处理申请，受理不会自动停用账号或删除业务数据。
- `vozeb_pro_rate_limits`：PostgreSQL 多实例共享的接口限流窗口，保存哈希后的业务键、原子请求计数和重置时间；数据库不可用时服务端临时退回进程内保护。
- `vozeb_pro_email_codes`：注册、换绑邮箱、找回密码验证码及失败尝试次数。
- `vozeb_pro_quota_usage`：套餐每日积分和次数占用。
- `vozeb_pro_point_records`：积分流水。
- `vozeb_pro_billing_products`：可售卖套餐商品，分别记录一次性永久积分、套餐有效期内每日赠送积分、价格、生效周期和上下架状态。
- `vozeb_pro_billing_orders`：商业订单主表，记录订单号、商品快照、套餐、金额、支付商单号、支付状态和生效信息；状态包括 `pending/paid/closed/canceled/refunding/refunded`，退款外部调用期间使用 `refunding` 认领状态。过期待支付订单由原子批处理更新为 `closed` 并记录 `close.source=expiration-job`，多实例使用 `FOR UPDATE SKIP LOCKED` 并发执行不会重复关闭。
- `vozeb_pro_payment_transactions`：支付流水，记录支付商交易号、支付渠道、金额、状态和原始回调摘要。
- `vozeb_pro_billing_reconciliation_runs`：支付商账单导入对账批次，保存渠道、来源、导入人、文件名、行数、匹配数、异常数和金额差额摘要。
- `vozeb_pro_billing_reconciliation_rows`：支付商账单对账明细，保存规范化后的订单号、支付商流水号、金额、币种、状态、本地匹配订单和差异代码；不保存整份原始 CSV。
- `vozeb_pro_user_plan_assignments`：用户套餐生效记录，用于保存由订单、CDK、管理员或系统发放产生的套餐权益周期。
- `vozeb_pro_payment_provider_events`：支付回调事件，用于保存支付商事件 ID、签名校验结果、原始 payload、`processing_at` 认领时间和处理状态，支持重复回调、超时接管和失败释放。
- `vozeb_pro_cdk_codes` / `vozeb_pro_cdk_redemptions`：CDK 和兑换记录。PostgreSQL 后台 CDK 列表使用数据库侧的关键词、状态筛选、聚合统计和分页，只读取当前页兑换明细；文件 Provider 保持兼容的内存筛选行为。
- `vozeb_pro_announcements`：站内公告。
- `vozeb_pro_prompts` / `vozeb_pro_prompt_seed_sources`：公共提示词、用户提示词和种子来源。
- `vozeb_pro_generation_logs` / `vozeb_pro_generation_log_assets`：图片/视频生成日志和结果资源地址；工作台日志通过 `conversation_id` 关联可恢复的 Agent 对话。
- `vozeb_pro_generation_tasks`：文本、图片、视频、音频、Agent 和短剧整集合成（`render`）异步任务状态，用于跨请求、重启和多实例查询；数据库状态统一为 `pending/running/success/error/paused/cancelled`，各上游或 Agent 的 `planning/completed/failed` 等状态会在写入索引列时归一化，原始状态仍保留在 JSON payload 中。表内同时预留 `conversation_id/run_id/surface/project_id/parent_task_id/attempt_no/client_request_id`，用于后台任务中心追踪会话、运行、项目、父任务、尝试次数和幂等请求。
- `vozeb_pro_creative_conversations`：统一创作会话，保存用户、`chat/canvas/drama` Surface、`agent/image-workbench/video-workbench/canvas/drama` 来源、可选项目、标题、状态、最近消息时间、持久滚动摘要和摘要覆盖到的消息序号；Surface、来源与项目创建后不可变。列表先按来源过滤再分页，避免不同工作台记录混入 Agent 历史。
- `vozeb_pro_creative_messages`：会话消息，按会话内连续 `sequence` 排序，保存角色、运行状态、正文、Run 关联和结构化 metadata。
- `vozeb_pro_creative_assets`：稳定创作资产，保存 `assetId`、来源 Run/任务/消息、父资产、顺序、文本内容或持久媒体位置及媒体信息；不保存 base64。
- `vozeb_pro_creative_run_events`：Agent Run 持久事件，使用递增 `bigserial` ID 为 SSE 断线续传提供精确游标。
- `vozeb_pro_canvas_projects`：Canvas 项目聚合快照，保存用户、标题、创作会话 ID、节点、连线、视口和项目助手会话；刷新或换设备后按登录用户恢复。
- `vozeb_pro_library_assets`：用户素材库聚合记录，保存文本或服务器媒体引用、标签、来源和备注；不保存媒体 base64。
- `vozeb_pro_local_media_assets`：图片、视频和音频的统一媒体登记表，保存稳定站内 `storage_key`、本地/对象存储 Provider、对象存储配置与对象 Key、同步时间、临时/长期分类、用户归属、原文件名、来源、会话/Run/任务/项目关联、MIME、大小和过期时间；媒体读取与删除以该登记和业务引用检查为权限边界。
- `vozeb_pro_drama_projects`：短剧项目聚合快照，保存用户、标题、状态和完整 `project_json`；项目内包含创作会话 ID、多集、角色/场景/道具/线索、内容审核状态、分镜及图片、视频、音频、整集合成任务状态，并按用户与更新时间建立列表索引。
- `vozeb_pro_drama_project_versions`：短剧项目独立版本快照，按项目保存递增版本号、保存原因、完整快照和创建时间；项目或用户删除时级联删除，`(project_id, version)` 保持唯一。

文本、图片、视频、音频和漫剧整集合成终态更新使用带 `user_id + task_type + allowed status` 条件的原子 `UPDATE`；任务尝试元数据通过存储层原子 mutate 合并，避免取消状态被旧快照覆盖。用户取消、后台成功、后台失败和过期检查同时发生时只有一个状态转换能成功，退款由成功抢占终态或检测到已取消结果的一方执行。

Agent Run 的状态与任务数组继续保存在 `generation_tasks.payload`，每个多副本子任务同时保存子任务 ID、完成状态、尝试次数和结果，恢复时复用已完成结果并继续轮询未完成任务；事件独立写入 `creative_run_events`。状态更新、助手消息终态和事件追加在同一 PostgreSQL 事务内完成；暂停、恢复、取消、完成和失败竞争时，旧 Run 快照不能覆盖更新后的状态。文件 Provider 使用串行 mutation queue 保持相同的进程内语义。

- `vozeb_pro_audit_logs`：登录、后台操作、CDK 兑换等安全审计记录。

## Repository 边界

`createPostgresRepositories()` 暴露表级 Repository：

- `settings`
- `users`
- `sessions`
- `points`
- `cdk`
- `announcements`
- `prompts`
- `generationLogs`
- `billing`
- `auditLogs`

业务层后续应通过 Repository 读写数据库，不再直接依赖 `.data/*.json` 路径。图片、视频和音频二进制不混入业务主库表：外部存储关闭时写入服务器数据目录，开启时新媒体只写 S3 兼容对象存储。

积分消费、失败退款和余额读取属于在线高频路径：PostgreSQL 使用定向的用户、套餐、每日钱包、额度和流水查询，并在同一事务中完成锁定、扣减/恢复和流水写入；不会为一次生成请求读取完整认证快照。完整快照读取仍保留给整库备份或兼容性路径，不能重新用于高频生成扣费。

## 当前接入状态

`web/src/lib/auth/store.ts` 已接入 PostgreSQL 快照读写：用户、会话、全局设置、套餐权益、系统渠道、积分流水、每日额度、CDK、邮箱验证码和公告会读写上面的关系表。系统渠道 API Key 在数据库中只保存密文，所有 PostgreSQL 设置读取路径必须在服务端解密后才能参与模型拉取、能力检测或按需显示。

`web/src/lib/prompts/store.ts` 以及 `web/src/lib/server/` 下的生成日志、统一创作运行时、Canvas 项目、素材库、短剧项目和审计日志 Store 已接入 PostgreSQL。对应 JSON Provider 保留为单机文件部署方式。媒体业务记录始终保存稳定站内路径；读取时按每条媒体登记的 `storage_provider` 选择本地文件或短期对象签名地址，不受当前外部存储开关影响。

外部存储开关只决定新媒体写入位置。开启后新上传和新生成媒体只写对象存储，不保留本地持久副本；关闭后新媒体恢复写入 `VOZEB_PRO_DATA_DIR`。后台可把已有本地登记分批迁移到对象存储，只有对象上传和登记更新成功后才删除本地源文件，失败文件保留用于重试。

`billing` Repository 已提供套餐商品、订单、支付流水、支付回调事件、用户套餐生效记录、支付商账单对账批次和对账明细的基础读写能力。当前已接入套餐商品配置 API、用户创建订单 API、订单列表 API、支付成功后开通套餐/发放积分服务、真实支付下单参数生成、后台账单导入对账，以及 `/api/billing/webhooks/{provider}` 支付回调入口。

后台支付配置已通过 `vozeb_pro_app_settings.payment_config` 保存；Stripe、支付宝、微信支付、PayPly 和人工确认的密钥会按字段加密存储。支付下单、回调验签和后台配置状态读取时优先使用后台保存值，环境变量仍作为服务器部署兜底。

全新 PostgreSQL 初始化后会写入 `free`、`creator`、`pro` 三档权益，并预置 `creator-monthly`、`pro-monthly` 两个可售套餐商品。重复执行 schema 初始化不会重复插入或覆盖运营后台后续修改。

## 支付配置

用户创建商业订单后，可调用 `POST /api/billing/orders/{id}/checkout` 生成真实支付下单参数。接口会校验订单归属和状态，然后按订单支付渠道返回 Stripe Checkout 跳转链接、支付宝电脑网站支付表单/链接、微信支付 v3 Native `code_url` 二维码内容，或 PayPly 自定义接口返回的支付链接、二维码内容、表单 HTML。

# Agent 任务

创作 Agent Run 复用 `generation_tasks` 持久化，`task_type = agent`，JSON payload 保存会话 ID、Surface、可选项目、用户需求、运行状态和任务计划；事件写入 `creative_run_events`，生成结果登记到 `creative_assets`。图片、视频、音频和文本子任务继续使用现有任务类型，并写入父 Run、会话、项目和尝试次数关联。真实执行状态以后端记录为准，画布节点 metadata 仅承担展示和关联。

规划模型读取当前会话最近 12 条已完成消息；更早消息按序写入 `creative_conversations.context_summary`，并用 `context_summary_through_sequence` 防止重复摘要。当前 Run 的用户消息和助手占位消息不会重复进入自身规划上下文。

任务可保存多份媒体引用。依赖任务完成后，执行器从其稳定 `assetId` 重新读取持久媒体位置并注入下游图片或视频请求；`parent_asset_id` 保存首个父资产，其余父资产 ID 记录在资产 metadata 中。

同一用户的 `client_request_id` 保持唯一。重复提交 Agent Run 时返回原运行，不重复创建用户消息、助手占位消息、子任务或计费。SSE 使用 `creative_run_events.id` 作为 `Last-Event-ID`，只重放游标之后的事件。

Chat 规划可以返回 Canvas 或短剧 `projectHandoff`。服务端使用 `handoff-{runId}` 作为稳定交接 ID，在所有生成任务完成后合并规划引用资产与本轮新资产，写入一次 `project.handoff` 持久事件，并将完整交接信息保存到助手消息 metadata 和 `run.completed`。Canvas 与短剧均通过服务端项目 API 按稳定交接 ID 幂等创建，不把媒体 base64 写入项目或交接记录。

`app_settings.generation_concurrency` JSONB 同时保存 `agent/image/video/audio/text/render` 六类单用户并发上限；Agent 新建、暂停恢复和失败子任务重试读取后台 `agent` 值，漫剧整集合成读取 `render` 值，不使用代码内固定常量。

`app_settings.generation_defaults` JSONB 还保存 `workbenchSmartPlanning.image/video` 两个工作台默认开关。后台关闭某一类开关后，公开会话会把该状态同步给对应工作台，前端要求用户先明确选择匹配的生成模型；未关闭的另一类工作台不受影响。

后台 Agent Skill 保存在 `app_settings.agent_skills` JSONB 字段中，包含名称、用途、执行规则、启用状态和触发关键词。系统默认内置并启用“电商生图”Skill，管理员可在模型渠道设置页修改、停用、删除或新增 Skill。

Skill 还可记录 `sourceUrl`、`sourceVersion` 和 `license`。默认电商生图 Skill 来源为 `buluslan/gpt-image2-ecommerce` v0.1.0（MIT），项目仅适配其工作流与模板匹配规则，不使用其 Codex CLI/Shell 执行链。
